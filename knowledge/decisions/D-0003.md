# D-0003 — Use Refined Tools models for body presentation

Accepted 2026-09-17 from Rusty's explicit model-priority correction.

Prefer Refined Tools wherever it supplies a model. Resolve items through Minecraft's
item renderer and the active resource-pack/model-loader stack. Keep normal modded or
vanilla fallback models for items the pack does not replace. Do not copy third-party
artwork into Quick Slot or force every item into a vanilla sprite.

The active Refined Tools 3.0 diamond sword definition chooses a sprite in GUI, fixed and
ground display contexts, and a 3D model in other contexts. The local pack uses Modefite
1.0.1+1.21.1 to load these newer definitions. Body rendering must select the intended
3D variant, including relevant item components, while HUD/inventory icons retain the
pack's intended GUI presentation. Verify this through the actual renderer before tuning.

Measure scale and clearance from the resolved model used on the body, after its display
transformation. Item identity alone is not a sufficient cache key when components or
display context change geometry. Invalidate model measurements and placement caches on
resource reload. Custom-rendered models without baked bounds require explicit measured
placement defaults/overrides and a real-client visual gate, never guessed sprite bounds.

Visual acceptance includes Refined Tools enabled, disabled and reloaded with F3+T; wide
and slim players; armor/backpacks/elytra; the pack's shaders; and an oversized modded item.
The scale target is a deliberately carried tool that fits the player's body naturally.

References: [Refined Tools](https://modrinth.com/resourcepack/refined-tools) and
[Modefite](https://github.com/TimmyChips/Modefite-Item-Defintion-Backport).
